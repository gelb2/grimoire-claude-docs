11. 불변 규칙 R1~R8

깨짐 시 작업 중단 → 복구 절차. CLAUDE.md §0 ZERO-TOLERANCE · §5 문서 피라미드 · §6 워크플로우 파생.

R1. 하위에서 상위 불일치 발견 시
→ 작업 중단 → 상위부터 수정 → 하위로 재전파. 코드를 고쳐서 상위 문서 불일치를 덮지 않는다.
R2. PLANNING 에 없는 기능을 코드가 구현 금지
→ 먼저 PLANNING_GRIMOIRE.md 업데이트 (사용자 승인 필수) → 구현.
R3. 정본 아닌 레포에서 직접 수정 금지
→ 예: web 의 api-contract.md 는 server 에서 먼저 수정 후 복사. pre-push docs 동기화 훅이 차단.
R4. 숫자 하드코딩 금지 (규칙 문서)
→ TECH_STATUS / CHANGELOG / CLAUDE.md 에 테스트 수·라우트 수·모델 수 숫자 박지 않는다. "npm test 실행으로 확인" 식 참조.
R5. 작가 소설 본문 수정·인용·로깅 금지 (전 에이전트 공통)
→ grimoire-web/DeerDevil_MDfiles/ · seed-data/classics/ · DB episodes.raw_md · episodes.blocks 모두 보호 대상. 리포트/커밋 메시지에 인용 금지.
R6. §0 원가 철칙 게이트 우회 금지
→ 새 AI 기능은 cost-accountant 마진 ≥3배 검증 없이 기획 진행 불가. qa 게이트가 배포 차단.
R7. 사슴악마 시각 정본 불일치 금지
→ 새 UI/테마/포맷 출력은 visual-canon-keeper 검수 필수. reports/VISUAL_CANON_REPORT.md CRITICAL 이 있으면 배포 차단.
R8. ACCOUNTS.md 전체 에이전트 참조 금지
→ Polar / Anthropic / OpenAI 시크릿 키 포함. 어느 에이전트도 Read 하지 않는다.

12. 검증 명령어

문서 정합성·에이전트 상태·배포 게이트 자동 확인. shell 에 복사 붙여넣기 가능.

# 1) docs/ 공유 정본 server ↔ web SHA256 일치 확인 (10 동기화 파일)
for f in api-contract.md data-model.md glossary.md environments.md \
         ai-analysis-spec.md TERMS_OF_SERVICE.md PRIVACY_POLICY.md \
         theme-spec.md design-tokens.md DEPLOY.md; do
  SERVER=$(shasum -a 256 grimoire-server/docs/$f 2>/dev/null | awk '{print $1}')
  WEB=$(shasum -a 256 grimoire-web/docs/$f 2>/dev/null | awk '{print $1}')
  [ "$SERVER" = "$WEB" ] && echo "✅ $f" || echo "❌ $f"
done

# 2) reports/ 파일 7~8개 존재 확인 (COST_ALERT 는 조건부)
ls reports/ | wc -l

# 3) research/ 파일 10개 확인 (루트 평평 구조 정리 후)
ls research/*.md | wc -l

# 4) 레포 각 main 기준 배포 버전 확인
(cd grimoire-server && git log -1 --format='%h %s' main)
(cd grimoire-web && git log -1 --format='%h %s' main)

# 5) 테스트 전수 (실측 명령으로 확인 — 숫자 하드코딩 금지 규칙)
(cd grimoire-server && npm test 2>&1 | tail -3)
(cd grimoire-web && npm test -- --run 2>&1 | tail -3)

# 6) 사슴악마 시각 정본 API 응답 확인
curl -s https://api.grimoire-book.com/api/themes/deerdevil | head -c 300
