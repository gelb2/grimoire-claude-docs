# 초기 참고자료를 개발 규칙으로 연결한 과정

Grimoire를 개발할 때 GMP를 AI의 초기 참고자료로 넣고 사용하기 시작했다. 기획 대화의 요구를 기능·제약·입출력·검사 기준으로 나누고, 여러 작업을 같은 문서 기준으로 이어가기 위한 구성이었다. 이 문서는 그 구상과 프로젝트에서 확인되는 활용을 설명한다.

## 참고자료를 배치한 방식

GMP는 요구사항을 나누고 프롬프트를 구조화하는 참고자료로 두었다. PRD 작성 프롬프트는 기획 대화를 개발 문서로 옮기는 데, 바이브코딩 가이드는 작업 단계와 인계 형식을 구성하는 데 참고하도록 배치했다. 당시 지침은 이 파일들을 역할에 따라 읽게 했다.

| 자료 | 프로젝트에서 참고한 내용 | 확인할 파일 |
| --- | --- | --- |
| [GMP-v2.2.md](GMP-v2.2.md) | 요구사항 분해, XML 구획, 핵심 제약의 앞뒤 배치, 우선순위, 자기검증 질문 | `.claude/AGENTS.md` §4, `.claude/agents/grimoire-planner.md` |
| [PRD 작성 참고 프롬프트](prd-generation-prompt-gmp2.md) | 기획 대화를 기능·입출력·처리 규칙·UI 동작으로 정리 | `.claude/prompts/planner.txt`, `PLANNING_GRIMOIRE.md` |
| [바이브코딩 작업 가이드](vibe-coding-unified-guide.md) | 작업 단계, 역할 분담, 문서 인계, 완료 전 확인 | `AUTOMATION.md`, `.claude/knowledge/agent-system.md` |

문서의 존재와 실제 실행은 구분한다. 지침에 적힌 모든 기법이 매 작업마다 실행됐거나 결과를 개선했다고 단정하지 않는다.

## Grimoire에 맞춰 구성한 부분

참고자료 다음에는 프로젝트의 구체적인 규칙을 붙였다. `PLANNING_GRIMOIRE.md`를 기획 기준으로 두고, 서버·웹 명세의 정본과 복사 관계를 정했다. 에이전트에는 담당 범위와 참조 문서를 연결했다. 프롬프트의 우선순위·제약 구획은 실제 `.claude/agents/`와 `.claude/prompts/` 파일에서 확인할 수 있다.

문서가 있다는 이유만으로 코드와 일치한다고 보지는 않았다. 공유 명세 비교, 변경 범위 검사, 회귀 검사처럼 파일이나 실행 결과로 확인하는 장치를 별도로 구성했다. 참고 프롬프트의 자기검증 문구와 실제 센서·테스트 실행 근거를 같은 것으로 취급하지 않는다.

확인 경로는 다음과 같다.

1. [기획](../PLANNING_GRIMOIRE.md)과 [문서 관계](../DOC_MAP.html)에서 작업 기준을 확인한다.
2. [당시 에이전트 지침](../.claude/AGENTS.md)과 실제 프롬프트에서 제약·역할·참조 입력을 확인한다.
3. [하네스 관계](../HARNESS_MAP.html), [구성 조사](../research/HARNESS_ENGINEERING.md), 실제 스크립트와 기록을 대조한다.

## 현재 읽는 방법

세 참고자료의 본문은 당시 입력으로 사용한 내용을 보관한다. 문서 속 배포·시드·서브에이전트 예시는 현재 작업의 실행 허가가 아니다. 현재 실행 방법은 루트 README와 최신 사용자 지시를 따른다. 과거 훅·센서·배포 명령을 이 자료를 읽었다는 이유로 자동 활성화하지 않는다.
