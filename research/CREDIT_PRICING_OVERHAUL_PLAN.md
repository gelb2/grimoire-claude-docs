## 1. 배경 및 문제 정의

### 1-1. 현재 크레딧은 정수(Int)다

`grimoire-server/prisma/schema.prisma:23` — `credits Int @default(0)`.
모든 기능이 정수 크레딧으로 차감된다.

| 기능 | 크레딧 차감 | AI 원가/회 | 비고 |
|------|------------|-----------|------|
| 테마 AI 생성 | 1 | ₩14.6 | 일일 무료 초과 시 |
| AI 작품 분석 | 4 | ₩60.4 | 고정 3유형 |
| AI 채팅 1턴 | 1 (코드 미연동) | ₩16.2 (가정값) | 현재 무료 |

### 1-2. 정수 크레딧이 채팅에서 깨지는 지점

테마·분석은 **1회 = 예측 가능한 고정 원가**라서 정수 크레딧이 맞다.
하지만 채팅은 한 턴의 토큰량이 케이스마다 10배 이상 벌어진다.

| 채팅 케이스 | 추정 input | 추정 output | 추정 원가 | 1크레딧 고정 시 |
|-------------|-----------|------------|-----------|------------------|
| 짧은 질문 ("이 문장 어색해?") | ~200 tok | ~150 tok | ≈ ₩3 | 베스트 ₩100 과금 → **과금 과다** |
| 보통 대화 | ~2,000 tok | ~800 tok | ≈ ₩16 | 원가표 가정값과 일치 |
| 긴 컨텍스트 (작품 전체 맥락 + 긴 답변) | ~8,000 tok | ~2,500 tok | ≈ ₩60+ | 베스트 ₩100 → 마진 ≈1.6× → **§0 위반(적자 위험)** |

> 위 원가는 Sonnet 4.6 기준 개략 추정값(연구 단계 정밀화 대상). 환율 ₩1,474.

**결론**: 채팅 1턴 = 1크레딧 고정은 짧은 턴엔 바가지, 긴 턴엔 적자다. 정수 크레딧은 연속·가변 소비를 구조적으로 표현하지 못한다. 이것이 사용자가 지적한 "디노미네이션(액면 단위 재조정)" 문제의 본질이다.

### 1-3. 채팅 인프라 미비

`ChatMessage` 모델(`schema.prisma:309`)에 **토큰 사용량 필드가 없다**(content만 저장). 어떤 과금 방식을 택하든 input/output 토큰 실측·기록 필드 추가가 선행 과제다.

## 2. 현황 분석

### 2-1. 크레딧 (PLANNING §8)

- **소비**: 테마 1 / 분석 4 / 채팅 1(미연동) / 독자→작가 선물 1·3·5
- **무료 적립**: 가입 3, 첫 작품 등록 2
- **유료 패키지**: 기본 5개 ₩2,000(₩400/개) · 인기 20개 ₩3,000(₩150/개) · 베스트 50개 ₩5,000(₩100/개)

### 2-2. 구독 플랜 (PLANNING §8 "구독 플랜 + 테마 슬롯")

| 플랜 | 테마 슬롯 | 일일 무료 생성 | 초과 시 | 월 가격 |
|------|----------|---------------|---------|---------|
| Free | 1 | 3회 | 1크레딧/회 | ₩0 |
| Pro | 3 | 7회 | 1크레딧/회 | **미정** |
| Premium | 8 | 12회 | 1크레딧/회 | **미정** |

- 슬롯 = 동시 활성화 가능 테마 수. 만기 시 시스템 테마(midnight) 폴백.
- **현재 구독은 "테마 슬롯"만 판다.** 채팅·분석과 무관.

### 2-3. 채팅

- `ChatSession`/`ChatMessage` 모델 + 서버·웹 구현 완료(`/dashboard/chat`).
- 크레딧 차감 미연동 → 현재 전면 무료. ai-cost-table §3-4 "Phase 5+ 연동 예정".

### 2-4. §0 크레딧-원가 철칙

- 판매 단가 ≥ 총 원가(AI 원가 + 결제 수수료) × 3.
- Polar 수수료 2.9% + ₩442 고정. 환율 1 USD = ₩1,474.
- `ai-cost-table.md` 수정은 grimoire-cost-accountant 승인 필수.

## 3. 개편 옵션 매트릭스

> 4개 접근법. 연구·시뮬 후 사용자가 택일(또는 조합).

### 옵션 A — 디노미네이션 (단일 통화, 잘게 쪼개기)

- 1크레딧 → N "포인트"로 액면 분할 (예: 1크레딧 = 1,000pt). 내부 회계는 포인트 단위.
- 기존 기능은 포인트 묶음으로 환산(테마 1,000pt / 분석 4,000pt). 채팅은 토큰 실사용 → 포인트 차감.
- **장점**: 단일 지갑 유지, 모든 기능 한 통화. 채팅 가변 비용을 자연스럽게 표현.
- **단점**: DB 마이그레이션(기존 `credits` ×N 일괄 환산 + 모든 차감/적립/로그/패키지/관리자 코드). 표시 UX("3,000pt" vs "3크레딧" 혼란 가능).
- **§0**: 포인트 단가 = 크레딧 단가 ÷ N. 채팅은 토큰원가 × 3 을 포인트로 환산 차감 → 자동 충족.

### 옵션 B — 이중 통화 (크레딧 + 토큰 미터)

- 예측가능 기능(테마/분석)은 정수 크레딧 그대로. 채팅만 별도 "토큰 미터" 종량.
- **장점**: 기존 크레딧 시스템 거의 무변경. 채팅만 신규 추가.
- **단점**: 지갑 2개 → 충전·잔액·정산 UX 복잡. 두 통화 간 전환 정책 필요.
- **§0**: 토큰 미터는 input/output 토큰 실측 × (원가×3) → 충족 용이. 단 미터 충전 패키지 별도 설계.

### 옵션 C — 구독 중심 전환 (채팅을 구독에 포함)

- 채팅을 구독 플랜의 fair-use 한도로 포함(Pro = 월 N턴 또는 월 N만 토큰, 초과 시 throttle 또는 소액 종량).
- 크레딧은 테마/분석 종량으로 유지.
- **장점**: 사용자 월 정액 예측 가능. 채팅 변동성을 플랫폼이 흡수 + 구독 가치가 "슬롯"을 넘어 실질 기능으로 강화.
- **단점**: fair-use 한도 설계 난이도. 한도 소진 시 UX. 헤비유저 적자 리스크.
- **§0**: "한도 내 누적 원가 ≤ 구독료 ÷ 3" 가 성립하도록 한도 설계.

### 옵션 D — 하이브리드 (구독 토큰 풀 + 종량)

- 구독 = 월 토큰 풀 제공(Free 소량 / Pro 중간 / Premium 대량). 풀 소진 시 크레딧(또는 포인트) 종량 차감.
- **장점**: 정액 안정성 + 종량 유연성. 업계 표준(Cursor, ChatGPT Team 등)에 근접.
- **단점**: 가장 복잡. 토큰 회계 인프라 + 풀 이월 정책 필수.
- **§0**: 풀은 C 방식으로, 종량분은 A/B 방식으로 각각 충족.

### 비교 요약

| 기준 | A 디노미네이션 | B 이중통화 | C 구독중심 | D 하이브리드 |
|------|---------------|-----------|-----------|-------------|
| UX 단순성 | 중 (단일지갑·표시혼란) | 하 (지갑2개) | 상 (월정액) | 중 |
| 채팅 변동성 대응 | 상 | 상 | 중 (한도제) | 상 |
| DB 마이그레이션 범위 | 대 | 중 | 소~중 | 대 |
| 기존 시스템 보존 | 하 | 상 | 중 | 하 |
| 구독 가치 강화 | 무관 | 무관 | 상 | 상 |
| §0 충족 난이도 | 하 | 하 | 중 (한도설계) | 중 |

## 7. 연구 종합 및 권고 설계안 (Phase R 완료, 2026-05-16)

> 산출물: `research/CREDIT_OVERHAUL_RESEARCH_COMPETITORS.md` (researcher), `research/CREDIT_OVERHAUL_COST_SIM.md` (cost-accountant).

### 7-1. researcher — 경쟁사·업계

- **LLM 요금제 3계층 추상화**: ① API(토큰 날것) ② 소비자용(메시지로 추상화 + 월정액 fair-use) ③ 하이브리드(구독료 = 동일 USD 가치 크레딧 풀 + 풀 소진 시 종량). Grimoire 작가는 토큰 개념이 없으므로 **②+③ 결합**이 적합 — 사용자가 정한 "구독중심+디노미네이션"이 정확히 이 결합.
- **대표 사례**: Cursor, GitHub Copilot(2026-06-01 전환) — 풀 크기를 "구독료와 동일 USD 가치"로 설계해 직관 이해. 저비용 기능은 풀 미차감으로 무료화 → 헤비유저 적자를 고비용 기능에만 집중.
- **디노미네이션 1:1,000 권장**: idle game 연구상 4자리(만 단위) 초과 시 인지 부담. 1:1,000이면 채팅 1턴=수십~수백 pt, 테마=1,000pt, 분석=4,000pt로 3~4자리 유지.
- **한국 차용**: 네이버 쿠키(1쿠키=100원 직관 환산)의 투명성, 노벨피아식 이중 재화 소진 우선순위.
- **Solvimon 인사이트**: AI 제품은 날것 종량 청구 대신 선불 크레딧 buffer를 써라 — 작가는 "예상 못한 청구"를 안 맞고 플랫폼은 §0 마진을 포인트 단가에 미리 박을 수 있다.

### 7-2. cost-accountant — 마진 시뮬

- **채팅 턴 원가(Sonnet)**: P50 ₩19.9 / P95 ₩84.0 / P99 ₩137.1. (Haiku: P50 ₩6.6 / P95 ₩28.0 / P99 ₩45.7)
- **현 정수 1크레딧 채팅 과금은 §0 정면 위반**: P95 안전배수 1.2×, P99 0.73×.
- **디노미네이션 1:1,000 권고** + `ceil(AI원가×3 ÷ pt단가)` 차감 규칙이면 누적 적자 구조적 불가(올림은 항상 사업자 유리).
- **구독 fair-use 한도(스트레스 P95)**: Pro ₩9,900 ≈ 27~36턴/월, Premium ₩12,900 ≈ 36~47턴, ₩19,900 ≈ 57~74턴. **Pro ₩4,900 + Sonnet은 13~17턴까지만 안전 → 위험**.
- **조건부 PASS**: ① ceil 차감 코드 강제 ② 채팅 토큰 실측 필드 선행 ③ fair-use 한도를 스트레스 P95 기준 고정 ④ 한도 초과분 포인트 종량 흡수.
- **Haiku 티어링**: AI 원가 67% 절감, fair-use 한도 약 3배. 짧은 턴 Haiku / 긴 턴 Sonnet이 최적.
- 테마/분석 기존 기능은 디노미네이션 후에도 안전배수 불변(3.48~3.80×).
- ⚠️ 채팅 토큰 분포 P50~P99는 실측 0건 기반 **가정값**. AI_COST_MONITOR.md stale(환율·모델가 만료) → S Phase에서 재검증 필요.

### 7-3. 종합 권고 설계안 — "구독 포인트 풀 + 디노미네이션 단일 통화"

두 연구가 일치 권고하는 설계:

- **단일 통화 디노미네이션 1:1,000**: 1크레딧 = 1,000포인트. 기존 잔액은 ×1,000 자동 환산.
- **차감 규칙**: 테마 = 1,000pt, 분석 = 4,000pt(기존 정수 환산). 채팅 = `ceil(AI원가 × 3 ÷ pt단가)` 종량.
- **구독 = 월 포인트 풀**: Cursor식 "구독료 = 동일 가치 포인트 풀". 풀 소진 시 충전 포인트로 종량 흡수(예상 못한 청구 없음).
- **모델 티어링**: 짧은 턴 Haiku / 긴 컨텍스트 턴 Sonnet → fair-use 한도 여유.
- **선행 과제(CRITICAL)**: `ChatMessage`에 `inputTokens`/`outputTokens`/`model` 필드 추가. 없으면 모든 차감액이 추측.

### 7-4. CRITICAL 차단 신호 3건

1. Pro ₩4,900 + Sonnet 채팅 조합 → 헤비유저 적자.
2. 채팅 토큰 실측 필드 없이 디노미 차감 구현 진행.
3. fair-use 한도를 현 가격 P95로 설정(스트레스 시 §0 위반).

## 8. 최종 확정 골격 (v4, 2026-05-16 — 비판적 재검토 + 7개 결함 해소)

> v3 §8은 표면 파라미터(비율·가격·모델)만 결정했고, 스키마를 결정하는 **구조**는 비어 있었다. 메인 비판적 재검토에서 골격 결함 7건 발견 → cost-accountant 재검증(`research/CREDIT_OVERHAUL_COST_SIM.md` §v2) + 사용자 결정으로 해소. **본 §8이 골격 정본.**

### 8-1. 통화·디노미네이션

| 항목 | 확정 |
|---|---|
| 디노미네이션 | 1크레딧 = 1,000pt, 단일 통화. **채팅이 구간 정액으로 결론났음에도 1:1,000 유지** — ① 미래 토큰 실측 동적 차감 전환 여지 ② 보너스율(+5%/+20%)·구간 정액(예: 긺 6,070pt)의 세밀 표현. 표시 큰 숫자는 천단위 구분·축약 UI로 완화. (입자도가 현 사용처보다 과한 것은 인지된 트레이드오프) |
| pt 단가 | **단일 일원화** — 모든 pt 동일 화폐가치. 수량 할인은 보너스 pt로만. 표면 단가 1pt = **₩0.12 확정**. §0 검증 기준은 **최악 실효 순단가 = ₩0.09856/pt**(입문 ₩3,000 충전 시 Polar 고정수수료 ₩449 잠식 반영). 모든 차감 N은 이 값 기준. |
| §0 기준 | "순수령액 ÷ pt수". 차감 N은 **스트레스 원가**(Sonnet+20% × 환율+8.5% = ₩1,624.33) 기준 `ceil(스트레스원가×3 ÷ ₩0.09856)`. cost-accountant v3 산출(`CREDIT_OVERHAUL_COST_SIM.md` §v3) 전 항목 §0 PASS — 단 경계선 운영(쿠션 거의 0). 환율 입력 ₩1,497.08(2026-05-16 재스윕). |

### 8-2. 포인트 출처·회계 (결함 1·5 해소)

포인트 출처 4종을 **분리 회계**한다. `Author.credits` 단일 Int로는 불가 → 출처별 분리 저장(필드 분리 vs ledger 테이블 — S Phase 스키마 설계 항목).

| 출처 | 성격 | §0 위상 |
|---|---|---|
| 무료 적립(가입·첫작품) | 매출 0 | §0 비대상 — CAC(마케팅비)로 회계 분리, 저원가 용도 제한 |
| 구독 월 풀 | 구독료 대응 | "월 한도 누적원가 ≤ 구독료 ÷ 3" |
| 응원 선물(독자→작가) | 독자 결제분 이전 | 독자 결제 시 §0 이미 충족 — 재검증 불요 |
| 충전(Polar) | 직접 결제 | pt 단가에 §0 박힘, 영구 보존 |

**소진 우선순위**: 무료적립 → 구독풀 → 응원선물 → 충전. (만료성 자원 우선 소진 + CAC/COGS 분리 집계)

### 8-3. 구독 (결함 3·4 해소)

구독은 **테마 슬롯 + 월 포인트 풀 병존 차등**.

| 플랜 | 월 가격 | 테마 슬롯 | 월 포인트 풀 (채팅·테마·분석 공용) | 일일 무료 테마 생성 | 풀 이월 |
|---|---|---|---|---|---|
| Free | ₩0 | 1 | 없음 | 3회 | — |
| Pro | ₩9,900 | 3 | **93,000pt** | 7회 | 매월 리셋 |
| Premium | ₩19,900 | 8 | **191,500pt** | 12회 | 매월 리셋 |

- **월 포인트 풀은 채팅·테마·분석 3기능 공용** (결함 1 해소). 일일 무료 테마 생성과의 관계는 **계층 구조**: 테마 생성 = ① 일일 무료 횟수 내 → 무료(풀 미차감) → ② 초과 → 공용 풀 차감 → ③ 풀 소진 → 충전 pt. 채팅·분석은 일일 무료가 없으므로 곧장 공용 풀 → 충전 순.
- 풀 크기 cost-accountant v3 확정: "월 풀 누적 스트레스 AI원가 ≤ 구독료 ÷ 3" 성립(Pro ₩3,021 ≤ ₩3,300 / Premium ₩6,221 ≤ ₩6,633). 풀이 공용이므로 채팅 전용 환산: Pro 보통구간 채팅 ~115턴 / Premium ~236턴 — 단 테마·분석 사용분만큼 감소.
- **풀 이월 금지** — 무제한 이월 시 §0이 0.14×로 붕괴(이월 pt는 마진 0). 미사용 아쉬움은 충전 pt 영구 보존으로 흡수.

### 8-4. 채팅·분석 과금 (결함 2·6 해소 — cost-accountant v3 확정)
