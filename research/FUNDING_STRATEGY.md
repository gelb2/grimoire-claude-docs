## 1. 프로젝트 개요 (지원 사업 제출용)

**서비스 핵심:** 작가가 집필한 소설을 게시할 때, 작품의 분위기와 세계관에 맞춘 '개인화된 디자인 테마'를 AI로 생성·적용하여 독자에게 시각적 서사를 함께 전달하는 플랫폼.

**기술 스택:** Next.js (FSD 구조) + NestJS (헥사고날 아키텍처) 독립 2-Repo 구조. Claude API 기반 테마 생성, Azure 클라우드 인프라.

**현재 상황:** 기술 설계는 엔터프라이즈급으로 구축 완료. '수익 회수'를 중시하는 공공 지원 사업이나 '문화예술 진흥' 사업에 효과적으로 제안하기 위한 논리 보강 필요.

## 2. 사업 신청 방향 (3가지)

### 방향 A: 콘텐츠 산업 혁신

기존 텍스트 중심 플랫폼(문피아, 카카오페이지 등)과 차별화되는 **'비주얼 내러티브 솔루션'**으로서의 가치.

**핵심 논리:**
- IP(지식재산권) 확장성 — 소설 테마가 곧 세계관 브랜딩 자산
- 텍스트 → 시각적 경험으로의 전환 = 콘텐츠 가치 증대
- 웹소설 → 웹툰/영상화 시 테마 자산이 IP 패키지에 포함

**핵심 키워드:** 비주얼 내러티브, IP 브랜딩, 콘텐츠 산업 혁신, AI 기반 디자인 자동화

**예상 비판 방어:**
- "소설의 본질보다 디자인이 우선인가?" → 테마는 서사를 보조하는 도구. 책 표지·장정 디자인이 소설의 본질을 해치지 않듯, 디지털 공간의 시각적 연출도 동일한 맥락.

---

### 방향 B: 기초 예술의 디지털 전환 (DX)

독립 작가나 순수 문학가들에게 **'디지털 브랜딩 도구'**를 제공함으로써 얻는 공익적/예술적 가치.

**핵심 논리:**
- 독립 작가가 플랫폼 종속 없이 자신만의 시각적 공간을 소유
- 순수 문학의 디지털 접근성 향상 — 젊은 독자층 유입
- 문예진흥기금 공략 — "디지털 시대의 문학 향유 방식 혁신"

**핵심 키워드:** 문화예술 디지털 전환, 독립 창작자 지원, 문학 접근성, 디지털 브랜딩

**예상 비판 방어:**
- "상업 플랫폼 아닌가?" → 독립 작가에게 무료 티어 제공, 순수 문학·시·에세이 등 비상업 콘텐츠도 동등 지원. 플랫폼 수수료 없이 작가가 직접 독자와 연결.

---

### 방향 C: 창작자 경제 (Creator Economy) SaaS

작가가 직접 테마 에셋을 제작·거래할 수 있는 **'에셋 마켓'**으로의 확장 가능성.

**핵심 논리:**
- 테마를 AI로 생성 → 커스터마이징 → 마켓에서 판매 = 작가의 추가 수익원
- 크레딧 기반 내부 경제 (독자 → 작가 크레딧 선물, 테마 구매)
- SaaS 모델로 구독 수익 + 마켓 수수료 = 실질적 ROI

**핵심 키워드:** 창작자 경제, SaaS, 에셋 마켓플레이스, 구독 수익 모델, ROI

**예상 비판 방어:**
- "수익 모델이 불확실하다" → 구독 플랜(테마 슬롯 제한) + 크레딧 선물 + 에셋 마켓 수수료의 3중 수익 구조. Supabase/Vercel 방식의 프리미엄 모델 검증됨.

## 3. 공통 방어 논리

| 예상 비판 | 방어 |
|----------|------|
| 소설에 디자인이 왜 필요한가? | 책 표지·장정이 소설의 일부이듯, 디지털 공간의 시각적 연출도 서사의 일부 |
| 기존 플랫폼과 뭐가 다른가? | 문피아/카카오페이지는 획일적 UI에 콘텐츠만 교체. Grimoire는 작가별 독립 시각 공간 |
| AI 테마가 작가의 창작인가? | AI는 초안 생성 도구. 최종 커스터마이징은 작가가 직접 수행. 도구의 자동화 ≠ 창작의 대체 |
| 시장 규모가 충분한가? | 한국 웹소설 시장 1조원+, 글로벌 웹소설 시장 급성장. 틈새 차별화로 진입 |
